# RBAC 批次 1：S1 安全缺口收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落实 `docs/testing/rbac-maturity-scorecard.md` 第 6 节批次 1 的 7 条 S1 登记册条目，堵住「分页有权限、详情/写无权限」与「角色编码子串误判」两条可利用链路，并用自动化测试锁住验收口径。

**Architecture:** 纯后端。读路径靠 `@DataPermission` 补挂到详情/查询 Mapper 方法；写路径在 Service 层用「先经权限查询再改」的归属断言（handler 本身不拦 `updateById`）；角色判定抽成共享常量精确匹配；关系表公开写入口收敛到 `assignSingleOrg`。配套单测/反射清单测试落在 `user_boot/src/test/java/com/alex/user/rbac/`。

**Tech Stack:** JDK 17 + JUnit 5 + Mockito（与既有 `DataPermissionScopeHandlerTest` 同栈）；MyBatis-Plus `@DataPermission`；`SystemException` / `ResultEnum`。

## Global Constraints

- **本批次只修批次 1 的 7 条 S1。** 不得顺手修 S2/S3/S4（级联删角色权限、菜单树、启停、乱码等属批次 2–4）。
- **后端跑测试必须用 JDK 17：** `$env:JAVA_HOME="C:\Program Files\Java\jdk-17"`，再 `mvn -pl alex_miaosha_user/user_boot -am test`。
- **角色编码精确匹配基准**（与登录上下文一致）：超管 `super_super`（见 `UserPermissionContextServiceImpl.SUPER_ADMIN_ROLE_CODE`）；机构管理员 `admin`（与现有 `DataPermissionScopeHandlerTest` 正例一致）。禁止继续使用 `code.contains("super"/"admin")`。
- **写路径归属策略：** 非超管在 update/delete 前必须先走已挂 `@DataPermission` 的 query；query 返回 null → 抛 `SystemException`（文案统一含「无权」），不得静默成功。
- **提交信息不得包含** `Co-authored-by: Cursor <cursoragent@cursor.com>`；Windows 下提交信息用英文。用户未明确要求 commit 时，计划内 Commit 步骤改为「暂不提交，等确认」。
- 分支：`develop-1.0-feature-org-manage`。

### Task 6: 关系裸 CRUD 收敛到 assign 语义（RBAC-BE-RELATION-001）

**问题：** `OrgUserInfoController.POST` → `addOrgUserInfo` 直接 `insert`，可绕过 `assignSingleOrg` 的「单用户唯一有效机构」。

**目标行为（最小改动、可测）：**
1. 公开 `addOrgUserInfo`：**禁止**再裸插 `status=有效` 的第二份关系。
2. 若请求带齐 `userId`+`orgId`，改为委托 `assignSingleOrg(Long, Long)`（复用锁与事务）。
3. `updateOrgUserInfo`：若把某行改成有效且会导致同一 user 多条有效，拒绝；或同样转调 assign。
4. Controller 仍可保留路径（避免前端立刻 404），但语义变成 assign。

**Files:**
- Modify: `.../orgUserInfo/service/impl/OrgUserInfoServiceImp.java`
- Modify（如需）：`OrgUserInfoController` 仅改 JavaDoc 说明「等价 assignSingleOrg」
- Create: `user_boot/src/test/java/com/alex/user/rbac/OrgUserAssignGuardTest.java`

**Steps:**

- [ ] **Step 1 — 红灯：** 模拟已有 `status=1` 关系时，再 `addOrgUserInfo(status=1)` 必须抛异常或转调 assign 后仍只保留一条有效（优先用 spy 验证 `assignSingleOrg` 被调用且 `insert` 不被直接调用）。

- [ ] **Step 2 — 实现：**

```java
@Override
public Boolean addOrgUserInfo(OrgUserInfoVo vo) {
    if (vo == null || vo.getUserId() == null || vo.getOrgId() == null) {
        throw new SystemException(ResultEnum.PARAM_ERROR, "用户机构分配参数错误");
    }
    // 公开写入口统一走唯一有效机构语义
    return assignSingleOrg(Long.valueOf(vo.getUserId()), Long.valueOf(vo.getOrgId()));
}
```

  （若 `userId`/`orgId` 在 VO 上已是 Long，去掉 `valueOf`。）
