### Task 2: D — Batch delete Modal.confirm

**Files:**

- Modify: `userManager/index.vue`, `roleInfo/index.vue`, `permissionInfo/index.vue`, `menuInfo/index.vue`

**Interfaces:**

- Consumes: existing `del*` / row selection state
- Produces: confirm-gated batch delete

- [ ] **Step 1: Pattern**

For each batch function, wrap delete:

```ts
import { Modal, message } from "ant-design-vue"; // only if file already imports from ant-design-vue; else match local style

const batchDelXxx = () => {
  if (!rowIds?.length) {
    message.warning("请先选择数据！", 3);
    return;
  }
  Modal.confirm({
    title: "确认删除",
    content: `确定删除选中的 ${rowIds.length} 条数据吗？`,
    okText: "删除",
    okType: "danger",
    cancelText: "取消",
    onOk: () => delXxx(rowIds.join(",")),
  });
};
```

Use the actual selection variable name in each file (`rowIds` / `selectedRowKeys` — read file first).

- [ ] **Step 2: Apply to all four pages**

Do not change single-row `a-popconfirm`.

### Task 3: C — User list filters

**Files:**

- Modify: `src/views/user/userManager/index.vue`

**Interfaces:**

- Produces: searchInfo fields `username|status|orgId|roleId` sent to `getUserManagerPage`

- [ ] **Step 1: Extend type**

```ts
// config/index.ts UserManagerInfo
roleId?: string;
// orgId/status already exist as string
```

- [ ] **Step 2: Load filter options on mount / when page opens**

```ts
const orgOptions = ref<{ label: string; value: string }[]>([]);
const roleOptions = ref<{ label: string; value: string }[]>([]);

const loadFilterOptions = async () => {
  const [orgRes, roleRes] = await Promise.all([
    getOrgInfoPage({ status: "1" } as any, 1, 1000),
    getRoleInfoPage({ status: "1" } as any, 1, 1000),
  ]);
  if (orgRes.code === "200") {
    orgOptions.value = (orgRes.data?.records || []).map((o: any) => ({
      label: o.orgName,
      value: String(o.id),
    }));
  }
  if (roleRes.code === "200") {
    roleOptions.value = (roleRes.data?.records || []).map((r: any) => ({
      label: r.roleName,
      value: String(r.id),
    }));
  }
};
```

Import APIs from existing `@/views/user/orgInfo/api` and `@/views/user/roleInfo/api`. Prefer typed imports from those modules' config types instead of `any` when easy.

Dict:

```ts
const { getDictByType } = useDictInfo("is_valid");
const statusOptions = computed(() => getDictByType("is_valid"));
```

Match exact dict type string used elsewhere in user module (search `useDictInfo` in orgInfo/userManagerDetail).
